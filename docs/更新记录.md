## v0.76.0

**新增 Agent 层，检索与现有问答接口不动**：`agent/` 下用 LangGraph 0.6 的 `StateGraph` 把链路显式拆成 `plan → search_kb → gate → generate → verify → finalize`，`verify` 第一次引用校验不过时换一个检索问题重新走 `search_kb`，第二次仍不过进 `refuse`，最多重试一次。`search_kb` 只把现有检索器包一层，BM25 / 向量 / RRF / Cross-Encoder 与 chunk 结构全都不变；生成、逐字校验、拒答、缺口日志复用 `answer/` 的同一套实现。新接口 `POST /agent/stream` 用 SSE 推 `status`（plan / search / tool / gate / generate / verify / retry / refuse）、`tool`（`search_kb` 的 query、命中数、耗时）、`delta`、`reset`、`error`、`done`；线程记忆默认 `InMemorySaver`，配 `DATABASE_URL` 时用 `langgraph-checkpoint-postgres` 的 `PostgresSaver`，复用同一个 PostgreSQL 16 并自动建表。线程按登录用户 / 匿名 IP 哈希隔离，换账号拿旧 `thread_id` 来会新建线程并标 `thread_reset`。前端输入条新增 **Agent** 开关（设备级偏好，不上传），回答下多一行「Agent · N 次 search_kb」，可展开工具调用与执行过程；关闭开关即回到原 `/chat/stream`。LangGraph 钉在 `>=0.6,<0.7`：0.7 / LangChain 1.0 起要求 Python 3.10，而本机、CI 与镜像仍按 3.9 维护，因此没有用 `create_agent`，用显式图更便于审计。测试 666 条通过（skip 13，新增 24 条 Agent 用例）；模拟 CI（不装 fastapi、装 langgraph）664 条通过（skip 18）。本机 mock 服务 `/health` 为 `agent=true / agent_checkpointer=memory`，`/agent/stream` 返回工具调用、引用与步骤，同一线程第二轮能带上历史改写追问；Edge 1440×900 与 390×844 实测 Agent 开关、工具展开、横向溢出 0、控制台 0 报错，截图见 `data/work/v076-agent-1440.png` 与 `v076-agent-390.png`。细节见 [Agent 层](Agent层.md)。**本轮没有部署**，线上仍是 v0.75.1。

## v0.74.5

**换账号不再串用上一个账号的对话**：个人数据先写本机，登录后按账号同步；原先换号登录只清了 localStorage，页面内存里还是上一个账号的对话，而新账号服务器上还没有内容时同步不会刷新页面，于是员工账号会看到老板的对话历史，下一次保存还会把它写进自己账号。现在换号登录会先把新账号的同步副本拉进本机，再整页重载，内容就位前不撤登录页；切回原账号仍能从服务器找回自己的对话，匿名数据首次合并的规则不变。用 CDP 驱动本机 Edge 实测：旧代码可复现串号，新代码下员工账号的界面、localStorage 与服务端副本都没有老板的对话，切回老板账号能找回；截图见 `data/work/v0745-crossaccount-staff-1440.png` 与 `v0745-crossaccount-staff-390.png`。**本轮没有部署。**

## v0.74.4

**追问判定不再误伤独立问题**：问题理解原先依赖「为什么 / 怎么 / 如何」作为追问信号，只要历史非空，「不想上班怎么办」这类与上文无关的独立问题也会被送去改写；模型判成「指代不明」后，接口在检索前直接回「我不确定你指的是哪道题」。现在只有「它 / 这题 / 呢 / 还有」这类真正的指代与承接词才触发改写，「其他 / 应该 / 因此 / 其中」里的同名汉字先剔除，真正的追问行为不变。测试 639 条通过（skip 13，新增 2 条）。**本轮没有部署。**

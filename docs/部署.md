# 部署（阿里云 / 腾讯云 ECS）

目标：把仓库一键跑成公网可访问的问答页，带访问口令、限流和每日额度上限。

```
浏览器 ──HTTPS──> Nginx(80/443) ──HTTP──> 127.0.0.1:8000 (uvicorn, 1 worker)
                                             └─ Docker 容器：FastAPI + BM25 + bge + Cross-Encoder
```

Docker 负责环境一致性和模型文件，Nginx 负责 TLS 和第一层限流，应用自己再做口令校验、按 IP
滑动窗口限流和全局每日上限。

## 1. 机器

| 项 | 建议 |
|---|---|
| 规格 | 2 核 4GB 起（精排模型常驻约 2~3GB 内存） |
| 系统盘 | 40GB 起（镜像约 6GB，Docker 构建缓存还需几 GB） |
| 系统 | Ubuntu 22.04 / 24.04 |
| 安全组 | 只开 22、80、443；**不要开 8000** |
| 地域 | 国内地域访问快，但域名走 80/443 需要 ICP 备案 |

没有备案域名时，先用 `http://公网IP/` 演示，口令必须设置；有域名后再加 HTTPS。

### 腾讯云轻量应用服务器

轻量也能直接跑，实测 2核4G / 60GB / 5Mbps 这一档可用（本项目在腾讯云北京轻量上验证过）：

- 镜像选 Ubuntu 22.04/24.04，套餐升级不改 IP、防火墙和到期时间。
- 防火墙在轻量控制台里配，放行 TCP 22、80、443，**不要放行 8000**。
- Docker 用腾讯云 apt 镜像装：

```bash
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli \
  containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER
```

- 拉 `python:3.11-slim` 走 Docker Hub 可能很慢，在 `/etc/docker/daemon.json` 里加
  `"registry-mirrors": ["https://mirror.ccs.tencentyun.com"]`，然后重启 Docker。
- 4GB 内存跑精排比较紧，务必加 2GB swap（见第 6 节后面的命令）。

## 2. 安装 Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
docker --version && docker compose version
```

国内机器如果拉镜像慢，可以在 `/etc/docker/daemon.json` 配镜像加速器，然后
`sudo systemctl restart docker`。

## 3. 拉代码

仓库是私有的，用只读 Deploy Key：

```bash
ssh-keygen -t ed25519 -C "ecs-408-rag" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub
```

把公钥加到 GitHub → 仓库 → Settings → Deploy keys（勾选只读，不勾写权限）。然后：

```bash
git clone git@github.com:gaozhe114514/408-rag.git
cd 408-rag
```

GitHub 22 端口不稳时，在 `~/.ssh/config` 里走 443：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
```

`ssh -T git@github.com` 看到用户名即成功。

## 4. 配置环境变量

```bash
cp .env.example .env
chmod 600 .env
python3 -c "import secrets; print(secrets.token_urlsafe(24))"   # 生成访问口令
nano .env
```

必填两项：

- `DEEPSEEK_API_KEY`：只要在服务器上，不要写进代码、README、提交记录或日志。
- `KB_ACCESS_TOKEN`：上面生成的口令，浏览器首次提问时输入。

可选：`KB_RATE_MAX` / `KB_RATE_WINDOW`（每 IP 问答限额，题库浏览不计数）、`KB_DAILY_MAX`（全局每日上限，建议
保持非 0，给账单封顶）。

日志目录要给容器里的 `appuser`（UID 1000）写权限：

```bash
mkdir -p logs
sudo chown -R 1000:1000 logs
```

## 5. 构建并启动

```bash
docker compose up -d --build
docker compose logs -f api
```

首次构建 10~30 分钟：装 CPU 版 torch、下载 `bge-small-zh-v1.5`（约 92MB）和
`bge-reranker-v2-m3`（约 2.3GB）、重建 2019 语料（`pipeline.build` + 已落盘的解析）。
模型层在镜像里，之后只改代码不会重新下载。

看到 `Uvicorn running on http://0.0.0.0:8000` 即可。健康检查有 180 秒启动宽限，首次加载
模型期间 `docker compose ps` 显示 `starting` 是正常的。

国内构建慢或模型下载失败时：

```bash
# Dockerfile 默认已走清华 PyPI 镜像和 hf-mirror；要换源时再覆盖
docker compose build \
  --build-arg PIP_INDEX_URL=https://mirrors.cloud.tencent.com/pypi/simple

docker compose up -d
```

> `files.pythonhosted.org` 在国内经常 ReadTimeout，默认源就是为这个改的。

不想把模型打进镜像（例如想挂载外部模型目录），加 `--build-arg PRELOAD_MODELS=0`，启动后
第一次请求会现下载。

4GB 内存建议加 2GB swap，避免模型加载的峰值把进程 OOM 掉：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## 6. 验证

```bash
curl -s http://127.0.0.1:8000/health
# {"status":"ok","chunks":47,"mode":"hybrid-ce","fuse_k":10,
#  "provider":"deepseek","auth_required":true}
```

```bash
TOKEN=$(sed -n 's/^KB_ACCESS_TOKEN=//p' .env)
curl -s http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -H "X-Access-Token: $TOKEN" \
  -d '{"query":"CSMA/CD 最小帧长怎么算"}'
```

预期 `refused=false`、`citations` 非空、每条引用的 `quote` 都能在题库原文里逐字找到。
首次请求要把精排模型加载进内存，可能要几十秒；之后每问约 6~10 秒。

再验证口令确实生效：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' -d '{"query":"LRU"}'
# 401
```

## 7. Nginx + HTTPS

```bash
sudo apt update && sudo apt install -y nginx
# Ubuntu 自带的默认站点会抢占 80，不删的话访问 IP 看到的是 nginx 欢迎页
sudo rm -f /etc/nginx/sites-enabled/default
sudo cp deploy/nginx.conf /etc/nginx/conf.d/408-rag.conf
sudo nginx -t && sudo systemctl reload nginx
```

浏览器打开 `http://公网IP/`，输入口令即可。`/health` 不带口令也能访问，只暴露 chunk 数和
模式，不暴露内容。

有域名（且已完成备案）时：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your.domain.com
```

certbot 会自动改 80/443 配置并续期。然后把 `deploy/nginx.conf` 里的 `server_name _;`
改成域名，后续改配置时别覆盖 certbot 写入的 443 段。

## 8. 日常运维

```bash
# 看服务日志
docker compose logs -f --tail=200 api

# 看拒答缺口（补资料的依据）
tail -f logs/gap_log.jsonl

# 更新代码
git pull
docker compose up -d --build

# 重启 / 停止
docker compose restart api
docker compose down
```

容器带 `restart: unless-stopped`，服务器重启后会自动拉起。`.env` 改动后执行
`docker compose up -d` 让容器重建（restart 不会重读 env_file）。

## 9. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 容器反复重启，`exit 137` | 内存不足。升到 4GB，或临时用 `KB_MODE=hybrid`（不加载精排，但拒答阈值失效，不建议公网用） |
| 构建卡在下载模型 | 确认 `HF_ENDPOINT=https://hf-mirror.com`；检查磁盘 `df -h`；重试 `docker compose build --no-cache` 前先确认网络 |
| 启动卡在 `Waiting for application startup`，容器内连着 hf-mirror | 模型已在镜像里，compose 默认设置 `HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1` 避免联网检查。若改了模型名，先用 `PRELOAD_MODELS=1` 重新构建；不要在运行时联网下载 |
| 构建报 `files.pythonhosted.org Read timed out` | Dockerfile 默认使用清华 PyPI 镜像；仍失败时用 `--build-arg PIP_INDEX_URL=...` 换腾讯云等镜像 |
| 构建时 apt 连不上 `deb.debian.org` | Dockerfile 已把 Debian 源换成腾讯云镜像；若仍失败，检查实例能否访问 `mirrors.cloud.tencent.com` |
| 页面提示 401 | 口令没填或填错；浏览器会存在 localStorage，可在输入框重填 |
| 页面提示 429 | 问答触发每 IP 限流或每日上限；改 `.env` 后 `docker compose up -d`，或等窗口过去 |
| `permission denied` 写 gap 日志 | `sudo chown -R 1000:1000 logs`，UID 以 `docker compose exec api id -u` 为准 |
| 健康检查 unhealthy，但手敲 curl 正常 | 检查容器内是否启动完成；`docker compose logs api` 里看模型加载是否报错 |
| 回答很慢 | CPU 精排本身约 5~7 秒；并发请求在单 worker 内串行排队，不要开多 worker |
| 公网访问 8000 不通 | 这是故意的：compose 只绑 `127.0.0.1`，公网必须走 Nginx |

## 10. 安全与成本清单

- 安全组只放 22/80/443；SSH 用密钥登录，禁用密码（可选）。
- `.env` 权限 600，永不提交；`git status` 里出现 `.env` 立刻停下。
- 口令用 `secrets.token_urlsafe` 生成，怀疑泄露就换一个并重启容器。
- `KB_DAILY_MAX` 保持非 0，DeepSeek 控制台再设一个余额/用量提醒。
- Nginx 的 `limit_req` 和应用限流是两层；只保留一层也能跑，但公网建议都留。
- 限流是单进程内存实现，`--workers 1` 才准确；要多实例必须换 Redis。
- 定期 `docker image prune` 清理旧镜像，避免 40GB 磁盘被构建缓存吃满。

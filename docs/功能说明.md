# 功能说明

这一页讲清产品做了哪些功能、各自的边界与权限规则。界面规范见 [design.md](../design.md)，接口参数见 [接口](接口.md)。

## 产品框架

打开即问答；导航为 **问答 / 知识空间 / 创作 / 任务清单**，手机底部同名 tab 栏。没有「模式切换」：一个 Agent 自动判断普通对话、查资料还是调工具。

- **问答**：流式输出。普通问题直接回答；问到资料时自动检索，引用逐字校验通过后才出现；校验失败重试一次，仍失败就拒答。回答下方可展开引用、召回资料、改写后的问题和执行过程，可复制或存到笔记本。
- **输入设置**：输入条只保留一个「设置」按钮，里面是资料范围（默认知识库 / 自己的库）和人格。人格只影响措辞，不改变事实、引用与拒答规则。
- **Agent**：`POST /agent/stream`。每次请求把 `search_kb`、`kb_overview`、天气、时间、计算、代码、网页搜索、网页正文的工具定义交给 DeepSeek，由模型自己调用；工具循环最多两轮，同一工具不重复。调用 `search_kb` 后仍过拒答闸门、生成并逐字校验。线程记忆按对话 id 存在内存或 PostgreSQL，换账号拿旧线程号会新建线程。详见 [Agent 层](Agent层.md)。
- **实时工具**：天气、时间、计算、代码执行、网页搜索、网页正文。工具失败会明说，不拿知识库片段凑答案；资料类问题不会误走工具。
- **知识空间**：知识库、聊天历史、笔记本、人格预设、技能、学习记忆。
- **创作**：选文档或演示文稿，写主题 → 确认大纲 → 下载 `.docx` / `.pptx` / `.md`。
- **任务清单**：三列待办 / 进行中 / 已完成，支持拖动、归档、关联对话。

## 知识库

结构是 **知识库 → 文档 → 可引用片段**。

- **默认知识库**：内置 6 篇示例资料，只读，**不用登录就能提问和点引用**。启动时从 `data/curated/default/` 灌入，可直接换成公司真实资料。
- **公司知识库**：登录后全员可读；管理员、建库人或被指定的成员可写。适合放公司制度、产品手册、流程文档。
- **个人知识库**：只有建库人可见，管理员也看不到。
- 未登录时 `/collections` 只返回默认库；公司库和个人库需要登录。未登录 401、登录无权 404（不泄露库是否存在）、内置库写操作 403。

### 文件进料

- 支持 PDF（pypdf）、docx、pptx、xlsx、md / txt / csv / json / html，以及 png / jpg / webp / bmp / gif / tif 图片 OCR。
- 图片走本地 `rapidocr-onnxruntime`，纯 CPU，不连外部服务；`KB_OCR=0` 可关闭。
- 上传先落 `processing`，后台解析 → 切分 → 向量 → `completed`；失败落 `failed` 并保留原因。
- 单篇 20–50000 字，同库最多 200 篇，同名文档按 sha256 去重；空库提问直接说「这个知识库里还没有资料」。

### 片段与原文

- 每篇资料切成若干片段，片段是引用校验的最小单位。
- 片段可逐段改、删、重新切分；修改带 `revision` 乐观锁，两边同时改时后保存的回 409。
- 引用带真实库 id、文档 id 与原文起止偏移，点开整篇资料并高亮被引用的原句。

## 检索、引用与拒答

- BM25（进程内）+ 向量（pgvector，bge-small-zh-v1.5）→ RRF → Cross-Encoder 精排（bge-reranker-v2-m3）。
- 引用必须逐字命中原文，去掉空白后不少于 10 个字；失败换查询重试一次，仍失败就拒答。
- 资料没覆盖就明说，并把问题、原因和最高分片段写进缺口日志，不硬编答案。
- 数量 / 名单 / 平均极值 / 全文总结类问题会读全同一库的片段（上限 3 万字符）；超过上限就明确告诉模型「没读全」，禁止报精确总数。

## 账号与跨设备同步

- 用户名 + 口令注册；口令 PBKDF2-HMAC-SHA256（21 万轮、每用户独立盐），只存哈希。
- 登录发随机 token，`user_sessions` 只存 SHA-256，30 天滑动过期。
- 个人内容（对话、笔记本、任务清单、人格、技能、记忆、偏好）按 `updated_at` 合并到 `user_data`；删除写墓碑，别的设备下次同步跟着删。
- 访问口令、账号 token、同步元数据不同步；同步值单键上限 512KB、一次最多 80 个键。
- 旧设备的 `408-*` 本地键会一次性迁移到 `yanju-*`；服务端仍接受旧键，并在读取时归一。
- 换账号时先清本机属于上个账号的数据，避免串号。

## 可选的 WeKnora 后端（默认关闭）

配了 `WEKNORA_BASE_URL` 与 `WEKNORA_API_KEY` 才会把用户资料库切到 WeKnora；不配就走本地进料。闸门、生成、逐字引用校验、拒答始终在本项目，不调用它的 `/knowledge-chat`。官方建议 4C8G，本项目线上 2C / 3.7G 跑整套不划算，所以默认关闭。接入细节见 [WeKnora接入.md](WeKnora接入.md)。

# 言据 · 架构设计（v0.2）

> 目标：让每个结论都能被读者自己验证；答不出来就明说，不硬编。
> 范围：通用资料问答，内置 408 真题语料作为开箱即用的语料；Web 优先，不做 App、不做支付、不做社区。
>
> v0.2 补了一节「实现现状」。设计稿里的目标架构不必全部落地，
> 但每一处偏离都要能说清原因，不能文档写一套、代码跑另一套。

## 0. 实现现状（2026-10）

| 设计稿 | 当前实现 | 说明 |
|---|---|---|
| PostgreSQL + pgvector | **已实现** | `chunks` / `meta` / `gap_logs` / `answer_cache` / `answer_feedback` 五张表，向量 `vector(512)` + HNSW |
| BM25（PG 全文检索） | **应用内 BM25 Okapi** | 中文 FTS 要 zhparser，2C4G 上多一个扩展不划算，见第 3 节 |
| bge-m3（1024 维） | **bge-small-zh-v1.5（512 维）** | 全 CPU 部署；换模型只需改环境变量并重建向量 |
| Qwen2.5-7B 做意图/改写 | **DeepSeek + 规则回退** | 少维护一个模型服务；没有 key 时规则也能跑 |
| Redis（限流/缓存） | **可选 Redis 限流** | 默认仍是进程内滑动窗口；配了 `KB_REDIS_URL` 且装了 `redis` 包就走共享计数，连不上自动退回内存。缓存仍在 Postgres |
| 对象存储（图片） | **不做** | 不存原文件：图片在本地做完 OCR 后只留识别出的文字与片段，PDF / Word / PPT 同理，所以不需要 bucket |
| 文件进料（v0.49，v0.50 加 OCR） | **已实现，本地解析** | `kb/parsers.py` 支持 PDF（pypdf）、docx（zip + `word/document.xml`）、pptx（按页序）、xlsx（v0.58 起：zip + `xl/workbook.xml` / `sharedStrings.xml` / `worksheets/*.xml`，按单元格坐标把一行还原成一条记录、列与列之间用竖线分隔——表格不要先导成 PDF 再传，PDF 里每列是独立文字块，姓名和状态会被拆进不同段落）、md / txt / csv / json / html（bs4 去脚本样式）；编码 UTF-8 / GB18030 / Big5 → chardet。图片（png/jpg/webp/bmp/gif/tif）走 `rapidocr-onnxruntime`（PP-OCRv4 ONNX，纯 CPU），长边缩到 2400px、置信度 <0.5 丢弃、识别不到 20 字明确报错；`KB_OCR=0` 可关闭。上传先落 `processing`，后台线程解析 → 切分 → 向量 → `completed`，失败落 `failed` + 原因。加密 PDF、旧版 `.doc`、超限文件明确拒绝。片段可逐段改删，带 `revision` 乐观锁；重新切分基于已存原文 |
| WeKnora 知识库后端（v0.48，可选） | **保留但不默认** | `kb/weknora.py` 只在配了 `WEKNORA_BASE_URL` 时接管用户资料库，不配就走 v0.49 的本地进料。不再作为默认的原因：官方建议 4C8G，线上 2C / 3.7G 跑整套 `app + docreader + postgres + redis` 没有余量。闸门、生成、逐字引用校验、拒答始终在本项目，不走 `/knowledge-chat` |
| 请求日志 / 评测结果表（v0.48） | **已实现** | `request_logs` 记方法、路径、状态、耗时、问句（不记 IP / UA，客户端只留 IP 的 SHA-256 前 12 位）；`eval_results` 存每次评测摘要。`GET /stats/requests`、`GET/POST /eval/results` 读写；写库在后台线程，失败不影响问答 |
| 账号与跨设备同步（v0.51） | **已实现** | 用户名 + 口令注册，口令 PBKDF2-HMAC-SHA256（21 万轮、每用户独立盐），库里只存哈希；登录发 32 字节随机 token，`user_sessions` 只存它的 SHA-256，30 天过期，退出即删。登录后浏览器把 `408-*` 个人数据（对话、笔记本、题库、精通之路、任务清单……）推给 `user_data`，按 `updated_at` 毫秒值「新的赢」合并；删除写成墓碑 `__408_deleted__`，别的设备下次同步才跟着删。前端拦截 `localStorage.setItem`，1.6 秒防抖自动推，拉回后整页刷新；凭据类键（访问口令、账号 token、同步元数据）双向禁同步。切账号时按 `408-sync-owner-v1` 清掉上一个账号的本机数据，不串号。登录失败 5 次 / 10 分钟按 `(IP, 用户名)` 限流；用户名不存在也跑一次等价的 PBKDF2，不让响应时间泄露账号是否存在。没有 `DATABASE_URL` 时退到进程内存，重启即丢 |
| 知识点树 / 考频 | **科目 → 章节 → 卡片，附考频** | 42 张卡片有科目/章节/关联题；多级父子树与考频趋势仍缺 |
| 应答缓存 | **已实现** | `answer_cache` 表，默认 24h，键含模式/provider/语料指纹；拒答不缓存 |
| 缺口统计 | **已实现** | `GET /stats/gaps` 按原因、按天聚合，并返回最近拒答 |
| 反馈缺口 | **后端已实现，前端入口已撤** | `POST /feedback` → `answer_feedback` 表（无库退 JSONL），`GET /stats/feedback` 给出有帮助率、差评原因与最近差评。按产品反馈，评分/差评界面操作太重，已从问答页与质量页移除；接口保留给后续分析 |
| 对话首页「问答」 | **已实现** | 默认落地页：按时段问候 + 倒计时/连续天数/近 7 天状态 + 四张按科目分组的推荐问题（点击直接发问）；侧栏会话按今天/昨天/最近 7 天/更早分组。桌面无页头、对话列 820px，移动端保留 52px 顶栏 |
| 流式问答 | **已实现** | `POST /chat/stream` 返回 SSE：`status`（plan/cache/retrieve/gate/generate/verify，资料不足改走通用回答时多一段 `general`）、`delta`（从流式 JSON 里增量剥出 `answer`，`answer/stream.py`）、`reset`（校验失败清空已显示文字）、`done`（最终 payload，与 `/chat` 同构）。校验不过 → reset → 重试一次 → 仍不过则 `done` 是拒答；停止生成只丢未校验的气泡 |
| 单一问答链路（v0.54，取代 v0.33 的两种模式） | **已实现** | 界面上不再有 `资料 / 日常` 切换，提问固定带 `mode=auto`。服务端仍先走「检索 → 拒答闸门 → 生成 → 逐字校验」；闸门判定资料不足（`low_score` / `no_hits` / `ambiguous` / 模型自述缺料）时，不当场拒答，改由 `answer/auto.py` 的 `should_fallback` 放行、`answer/daily.py` 的通用提示词直答：正文首句由服务端固定加上「资料里没有直接依据」，不带引用、不写缓存，元信息写「通用回答 · 资料未覆盖」（切自建库写「…知识库未覆盖」），缺口照常写 `gap_log`，指标 `chat_fallback` 计数。引用校验失败、生成服务异常、语料为空、服务器未就绪**仍拒答**，绝不偷换成通用回答。`mode=kb`（严格只按原文、资料不够就拒答）与 `mode=chat`（旧版日常对话，不检索）保留给脚本与老客户端，界面不再暴露。返回的 `mode` 字段区分 `general` / `chat` / 资料问答三支，前端据此刻元信息 |
| 陪伴页「今日」 | **已实现（隐藏路由）** | 前端本地数据：初试倒计时（可改）、连续学习天数、近 7 天问答/练习量、今日一题（错题 → 上次引用 → 随机单选题，当天固定）、常驻提问框、答完题后的「再练一题 / 问为什么 / 看考点」、接着上次（对话/练习）。v0.23 按产品决定退出主导航，`#/today` 仍可直达；不登录、不上传 |
| 实时数据问答提速（v0.57） | **已实现** | ① 天气 / 时间 / 计算这类问法，双路召回同时很弱（BM25 top1 < 5.0 且向量 top1 < 0.55）时跳过 cross-encoder 精排，省掉 2C 机器上 5~7 秒——这类问题的答案不在静态语料里，精排只会把噪声排上来；只在 `_live_query` 判定有实时工具会触发时才启用，在库问题照旧精排，`timings.rerank_skipped` 与执行过程里都写明「跳过精排」。② 天气 / 时间 / 计算 / 学习进度 / 代码五类工具在检索开始时进 `_TOOLS_POOL` 后台并行跑，真降级到通用链路才取结果（`TOOL_WAIT_S=9`）；搜索与抓网页仍只在降级时执行，不抢跑。③ 天气工具 HTTP 超时 6→4 秒，地名坐标按城市缓存 24 小时；地名解析切掉「什么样 / 怎么样 / 情况」等问法尾巴，修掉「开封市什么样」整串当地名导致的工具失败。④ 通用链路服务端强制的那句「资料里没有直接依据」被模型复述时，`strip_echo` / `_strip_echo_stream` 去重，流式下只攒开头几个字判断，不拖慢首字。⑤ 前端等待行显示已等秒数（`.stream-elapsed`）。本地实测同一条天气问题首字 2.4~3.8 秒、整段 3.4~5.2 秒 |
| 个性化学习「学习」 | **已实现（v0.34 重做导师会话）** | 「精通之路」照 DeepTutor 走完整新建流程：①弹层里写学习目标（≤2000 字）+ 选一枚徽标；②勾资料（知识库 / 考点 / 题库 / 对话，可不选，每项带 `kind` 与 `detail`）；选完进详情页的**导师工作台**——左边大纲树、右边会话。导师先读资料，再从学习档案里挑 1–4 个问题问（提问卡：多题切换、选项带说明、可自由作答、可跳过），答完起草 4–8 个模块、每模块 2–6 个知识点（`memory / procedure / concept / design`）与一句能力型 `objective`；之后说改哪里只动那一块，服务端按名字沿用旧 id 与 `done`。关联真题按名字匹配考点卡，挂上的才自测。没排大纲的路线在详情页有「还没有大纲」落点（回导师页或按科目自排）。进度与会话存 localStorage，走完整条路写学习日志并标记 `completedAt`；v0.55 起从定大纲切到学习时自动发一条开讲请求，在定大纲里说「开始学习吧 / 继续学」也由前后端各判一次意图，在同一轮切模式并开讲；v0.56 起详情页改成整页工作台：桌面隐藏页头与子导航，路线信息收进左栏顶部，左栏（路线信息 + 大纲）从视口顶边到底边与侧栏同高，会话跨满右列、像正常「新对话」；手机保留页头，顺序为路线信息 → 会话 → 大纲。「练习」保留原有单题训练。书籍与沉浸式阅读按产品要求未做 |
| 资料范围提示（v0.58） | **已实现** | 输入条的库胶囊在未选库时写「408 内置」而不是「全部资料」——空串只查内置 408 语料，用户上传的资料在自建库里，原文案容易被读成「包含我上传的」。拿到通用回答（`mode=general` 且 `collection` 为空）时，最后一条回答下面补一条换库提示：「刚才只查了内置 408 语料。你导入的资料在「X」里。」+「切过去再问 →」，点了 `setChatCollection()` 切到最近更新的自建库并把原问题重发；没有自建库时整条不出现 |

## 1. 在线链路（对应 fig1）

```
提问
 → ① 接入层（Nginx 限流 / FastAPI 编排 / 日志 / 成本记账）
 → ② Query 理解（意图分类 · 指代消解 · 术语归一）   [DeepSeek + 规则回退]
 → ③ 双路召回：BM25（应用内 bigram）+ 向量（pgvector + bge-small-zh-v1.5），各 top-50
 → ④ RRF 融合 → top-30
 → ⑤ 精排 Rerank（bge-reranker-v2-m3）→ top-5
    （v0.57：天气 / 时间 / 计算这类实时数据问题，若 ③ 的 BM25 分与向量分同时低于
     `_SKIP_BM25=5.0` / `_SKIP_VEC=0.55`，跳过 ⑤ 直接进 ⑥ 判不通过——静态资料库里
     不可能有「今天开封市」的原文，精排救不回来，白等 5~7 秒。只在有实时工具会触发时生效）
 → ⑥ 拒答闸门（分数绝对值 + top1/top2 margin + 必含术语）→ 不通过则拒答 + 写缺口日志
 → ⑦ 生成（DeepSeek-V3，强制 JSON：结论 + 引用 + 原文片段；流式）
 → ⑧ 引用校验（引用片段必须是 chunk 原文子串）→ 不过则重试 1 次 → 降级为「资料未覆盖」
 → ⑨ 组装响应（答案 + 引用 + 页码锚点 + 耗时/成本）
 → ⑩ 前端渲染（KaTeX / 引用高亮 / 点击跳原文）

流式（`/chat/stream`）不改变链路顺序，只改变交付方式：⑦ 的 JSON 边到边解析，
只把 `answer` 字段的值吐给前端；⑧ 校验失败时发 `reset` 清空已显示文字再回到 ⑦，
最终以 ⑨ 的完整 payload（`done`）为准。引用块与「复制 / 存到笔记本 / 记入日志」
只在 `done` 之后出现——**流式只提前显示文字，不提前证明文字可信**。

v0.57 起等待时间不再串成一条直线：天气 / 时间 / 计算 / 学习进度 / 代码这五类轻量工具在 ③
开始时就被丢进 `_TOOLS_POOL` 后台线程跑，只有 ⑥ 判定不通过、真要降级到通用链路时才
`_tool_results()` 取结果（上限 `TOOL_WAIT_S=9` 秒，超时写「没在规定时间内返回」）；搜索与抓
网页不预取，资料能答时不白打外部接口。天气工具单次 HTTP 超时 6→4 秒，地名→经纬度结果按
城市缓存 24 小时；地名解析会把问法尾巴（「什么样」「怎么样」等）切掉，「开封市什么样」只在
v0.56 之前会整个当城市名去查、直接失败。通用链路前面那句「资料里没有直接依据」由服务端
强制加，模型若把整句抄一遍，`answer/daily.py` 的 `strip_echo` / `_strip_echo_stream` 会去掉
回声（流式下先攒开头几个字再判断，不属于回声就立刻放行，不拖慢首字）。前端等待行右侧
显示已等秒数（`.stream-elapsed`，规范见 design.md v2.28）。
```

出题（`/bank/generate`）是链路外的旁路，不进检索库：前端把用户粘贴的资料整段发给服务端 →
一次模型调用（强制 JSON）→ 沿用 ⑧ 的逐字校验思路（`source_quote` 去空白后必须出现在资料里，
至少 8 字）→ 通过的题由前端存进本机题库。资料用完即弃，不落盘、不建 chunk、不影响语料指纹。

选知识库提问时链路不变，只换语料：请求里的 `collection` 为空或 `cs408` → 408 内置语料（原
`chunks` 表）；否则拿该库的 `doc_chunks` 建/复用独立 searcher，③ 的向量召回在 SQL 里加
`WHERE collection_id = %s`，④–⑧ 与 408 完全一致，但 ③ 跳过题号解析、⑦ 换用资料问答 prompt。
库不存在回 404，库存在但还没资料直接拒答（`reason: empty_collection`），不落到「服务未就绪」。

## 3. 选型表：为什么是它

| 位置 | 选择 | 为什么不选另一个 |
|---|---|---|
| 向量库 | **pgvector** | 数据量只有几千 chunk，Qdrant/Milvus 是过度设计；pgvector 和业务表同库，能一条 SQL 做过滤（按科目/年份/知识点），省一个服务 |
| 关键词检索 | **应用内 BM25 Okapi** | 实测 pg 的 `simple` 配置对中文近乎无效，zhparser 要编译扩展、还要维护词典；几百个 chunk 的 BM25 用纯 Python 毫秒级算完，没必要搬进数据库。数据量到十万级再考虑 ES |
| Embedding | **bge-small-zh-v1.5** | 512 维、CPU 可跑，2C4G 服务器上能把首响压在十几秒；设计稿里的 bge-m3 更强但 2.2GB，本地 CPU 反而拖慢整体延迟。换 bge-m3 时只需改 `KB_EMBED_DIM=1024` 并重建向量 |
| 精排 | **bge-reranker-v2-m3** | 408 是「一字之差」密集型，Cross-Encoder 是刚需。别用 LLM 直接打分（贵且不稳定） |
| 生成 | **DeepSeek-V3** | 中文强、便宜、支持 JSON 模式；Qwen-Max 作备选做 A/B |
| 轻任务 | **Qwen2.5-7B-Instruct** | 意图分类/改写这类任务不需要大模型，小模型省一半钱、快一倍 |
| 融合 | **RRF** | 不用分数加权：BM25 与余弦相似度量纲不同，按排名融合更稳 |
| 拒答 | **阈值 + 规则** | 不用 LLM 判断「该不该答」：多一次调用、多一份不稳定，且无法解释 |

## 4. 数据模型（实际落地）

```sql
chunks
  id, kind(question|knowledge), year, seq, subject, chapter, title
  search_text         -- 浏览页搜索用（小写合并文本）
  text                -- 召回与引用正文：题干+选项 / 考点卡片
  answer, analysis
  payload jsonb       -- 原始 JSONL 行，浏览接口直接下发
  related_question_ids text[]  -- 考点 → 题目双向关联
  embedding vector(512)
  updated_at

collections      -- 用户知识库：id / name / description / created_at / updated_at
                 --   owner_id（users.id，个人库的建库人）/ created_by
                 --   visibility(shared|private；内置库不在此表)
collection_members -- collection_id,user_id 主键 / role(editor|viewer)
                 --   公司库的写权限名单；个人库不用
documents        -- id / collection_id / title / text / sha256 / created_at
                 --   status(processing|completed|failed) / error / bytes
                 --   source（扩展名）/ updated_at
doc_chunks       -- id / collection_id / document_id / seq / text
                 --   start_off,end_off（原文偏移，前端据此高亮原句）
                 --   revision（乐观锁，每次改 +1）
                 --   embedding vector(512)
meta            -- corpus_fingerprint / embedding_model / embedding_dim
gap_logs        -- id / query / reason / top_chunk / top_score / created_at
answer_cache    -- cache_key / query / payload jsonb / created_at
answer_feedback -- id / query / answer / helpful / reason / note
                --   citations text[] / cached / created_at
users           -- id / username / username_key（唯一，大小写不敏感）
                --   password_hash（pbkdf2_sha256$轮数$盐$哈希）/ created_at
                --   last_login_at / role(admin|member)
user_sessions   -- token_hash（SHA-256 主键）/ user_id / created_at
                --   expires_at（30 天；过期行登录时顺手清）
user_data       -- user_id,key 主键 / value jsonb / updated_at
                --   按 updated_at 合并；删除写 __408_deleted__ 墓碑
```

设计稿里的 `kp`、`qa_log`、`eval_item` 仍是规划：知识点现在是 `knowledge` 类型的 chunk（带 subject/chapter，没有父子树）；请求日志先由 Nginx access log 承担；评测集是文件（`data/eval/*.jsonl`），还没有入库。

默认入口是问答；问答、今日、学习、学习空间、任务清单共用浏览器 localStorage（对话、练习记录、精通之路、笔记本、学习日志、人格、技能、学习记忆、任务清单任务，以及自建题库 `408-decks-v1` 与题库题目 `408-deck-questions-v1`），倒计时、连续天数、当天题目、精通之路进度与「接着上次」都由前端本地计算，不入库。**不登录时**这些只在本机，换设备或清缓存会丢；**登录后**（v0.51）会自动同步到 `user_data`，换设备登录同一账号即可拉回，退出登录只清 token、本机内容保留。**知识库是例外**：资料在服务端（有库进 `collections` / `documents` / `doc_chunks`，没库退 `data/work/kb/library.json`），换设备能接着用；浏览器只记「上次选的哪个库」（`408-chat-collection-v1`）。

风格注入只在生成阶段生效：`style` 进入 system prompt 的措辞段，引用必须逐字命中、资料未覆盖必须拒答这两条硬规则在服务端独立校验，前端改不了；缓存按 `sha1(style)` 分命名空间，同题不同人格不会互相命中。

**硬约束**：一道题 = 一个 chunk（题干 + 选项 + 答案 + 解析 + 图），不切开。

## 5. 三个必须能辩护的设计决策

1. **为什么双路召回而不是纯向量**
   纯向量对「根本政治制度 / 基本政治制度」这类一字之差的表述召回不稳；BM25 + 领域词典兜住精确匹配，向量兜住口语化提问。

2. **为什么要有独立的引用校验环节**
   prompt 里写「必须引用」不等于模型真的引用了原文。用「引用片段是否为 chunk 原文子串」做程序化校验，是把「相信模型」换成「验证模型」，这一步是拒答率之外最能讲的技术点。

3. **为什么拒答阈值要靠评测集扫出来**
   拍脑袋定 0.6 的阈值在面试里一问就穿。正确做法：200 条评测集（A 资料内可答 / B 资料外 / C 跨知识点），扫阈值画曲线，选 B 类拒答率高且 A 类误拒率低的点，并报出这两个数。

## 6. 成本与容量

- 单次问答：rerank（约 5 条 × 长文本）+ 生成（约 2k token 输入） ≈ **0.005–0.02 元**
- 日 500 次问答 ≈ 3–10 元/天
- 服务器：2C4G 足够（模型全走 API），约 60–100 元/月
- 缓存：同一 query 的答案缓存 24h（`KB_CACHE_TTL`，0 关闭），命中率通常 15–25%，直接省这部分成本；只缓存作答成功的回答，拒答不缓存

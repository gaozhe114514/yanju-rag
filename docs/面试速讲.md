# 言据 · 面试速讲

> 当前线上 0.80.0，483 条测试通过。

## 30 秒版本

言据是一个「通用 Agent + 可引用知识库」。普通问题直接聊；问到公司资料、产品手册或个人文档时，Agent 调用 `search_kb` 检索，回答必须逐字命中原文并带引用；资料没覆盖就拒答并写缺口日志。Agent 用 LangGraph + DeepSeek 原生函数调用，知识库是其中一个工具，另外还有天气、股票、汇率、空气质量、IP、单位换算等 11 个日常工具。

## 2 分钟版本

1. **入口**：单文件前端，SSE 流式；Nginx 后面是 FastAPI。
2. **Agent**：每次请求把工具定义交给 DeepSeek，模型自己决定直接回答、调工具还是查知识库；工具循环最多两轮，同一工具不重复。
3. **知识库**：默认库内置只读、免登录可试用；公司库登录后全员可读；个人库只有本人可见。
4. **检索**：应用内 BM25 + bge-small-zh 向量 + RRF + bge-reranker 精排，向量存 PostgreSQL + pgvector。
5. **引用**：生成强制 JSON；每条 quote 必须逐字命中原文，失败换查询重试一次，仍失败就拒答；拒答写缺口日志。
6. **进料**：PDF / Word / PPT / Excel / 图片 OCR 本地解析，切分成片段，带原文起止位置，引用可回跳高亮。
7. **部署**：Docker Compose + Nginx，单机 2C / 3.7G；模型烘进镜像，线上不需要 GPU。

## 关键技术决策

- **为什么不用现成 ReAct 直接出答案**：引用必须逐字校验，所以 `search_kb` 一旦被调用，就把控制权交回原来的 gate → generate → verify 链路，而不是让模型拿片段自由作答。
- **为什么 BM25 在应用内**：中文 FTS 要 zhparser 一类扩展，2C4G 上不划算；数据库负责存储、过滤和 pgvector 向量检索。
- **怎么防胡编**：检索不到就拒答；引用 quote 逐字比对；表格数字由服务端数行后写进 prompt，答案数字对不上也拒答。
- **怎么控成本/延迟**：工具最多两轮；Agent 最多两路并发；DeepSeek 超时 45 秒；前端 50 秒无事件断开；应答缓存。
- **权限**：内置 / 公司 / 个人三层；`can_read` / `can_write` / `can_manage` 是纯函数，每个资料、片段、成员、问答入口都重新判权。

## 常见追问

**Q：为什么不用 LangChain 的 Agent 一把梭？**
A：检索后的引用校验、拒答和缺口日志是本项目的硬约束，通用 Agent 的最终回答不好做逐字校验；所以只借用工具调用循环，知识库分支接回自己的校验链路。

**Q：资料很多、读不全怎么办？**
A：统计 / 名单类问题走服务端表格统计，最多读到 4 万字；超过就明确告诉模型「没读全」，禁止报精确数字；普通问答只补命中片段的前后邻居。

**Q：怎么保证不串库、不越权？**
A：库分内置 / 公司 / 个人；每个入口重新判权；未登录 401、无权 404、内置库写 403；缓存键和缺口日志都带 collection 维度。

**Q：为什么默认库不用登录？**
A：它是内置只读示例库，给访客试用；公司库和个人库仍然要登录。写操作对内置库直接 403。

**Q：线上多大机器？**
A：2C / 3.7G 腾讯云轻量，单 worker，模型全 CPU；精排是主要延迟来源，所以只精排 10 个候选。

**Q：如果继续做，优先做什么？**
A：跨库检索与引用归属、更稳定的搜索源、真实公司资料上的评测集（拒答率 / 引用通过率 / 人工反馈）。

# 在线问答与接口

前端与脚本调用的 HTTP 接口、启动方式、访问口令与限流规则。

## 启动

```bash
# 无 API key 先跑通链路：mock provider 只取 top-1 的答案，不是真生成
KB_MODE=hybrid KB_PROVIDER=mock py -m uvicorn api.app:app --host 127.0.0.1 --port 8000

# 接 DeepSeek；hybrid-ce 默认启用拒答阈值 0.1/0
set DEEPSEEK_API_KEY=sk-xxxx
set KB_MODE=hybrid-ce
set KB_FUSE_K=10
set KB_CACHE_TTL=86400
py -m uvicorn api.app:app --host 0.0.0.0 --port 8000
```

默认知识库的示例资料在 `data/curated/default/`，启动时自动灌入；不需要再准备题库文件。

## 问答接口

| 接口 | 说明 |
|---|---|
| `POST /ask` | 单轮问答：`{"query", "style"?, "collection"?}`，返回 answer / citations / refused / reason / hits / latency_ms / cached |
| `POST /chat` | 多轮问答：`{"query", "history", "style"?, "collection"?, "mode"?, "tools"?}`；返回 `intent`、`rewritten_query`、`trace.steps` |
| `POST /chat/stream` | 同参数 SSE：`status` / `delta` / `reset` / `error` / `done`；引用校验未过时 `reset` → 重试一次 |
| `POST /agent/stream` | 统一 Agent SSE：`status`（plan / route / search / tool / gate / generate / verify / retry / refuse / done）、`tool`、`delta`、`reset`、`error`、`done`（多带 `thread_id` / `tool_calls` / `agent`）。引用校验最多重试一次；线程记忆按 `thread_id` 存在内存或 PostgreSQL |
| `POST /feedback` | 回答反馈：`{"query", "helpful", "reason", "note", "answer", "citations", "cached"}`；不占问答额度 |

`collection` 为空表示默认知识库；其他值是知识库 id。`tools` 是设置页开着的工具名，Agent 自己决定用不用。`style` 只影响措辞，不改变事实、引用与拒答规则。

## 知识库接口

| 接口 | 说明 |
|---|---|
| `GET /collections` | 当前可见的库。未登录只返回内置默认库（`builtin=true`）；登录后返回公司库 + 自己的个人库，带 `visibility` / `my_role` / `can_write` / `can_manage` |
| `POST /collections` | 新建：`{"name", "description", "visibility": "private|shared"}`；建公司库要求管理员 |
| `GET /collections/{cid}` | 库详情、文档列表与 `folders` 路径列表；无权回 404 |
| `PATCH /collections/{cid}` | 改库名 / 说明 / 每库切片参数：`chunk_target`（120–2000）、`chunk_overlap`（0–1000，且不超过一半） |
| `DELETE /collections/{cid}` | 删库（连文档、片段、成员、文件夹）；内置库 403 |
| `GET/POST/DELETE /collections/{cid}/folders` | 文件夹树：列表、新建（`{"path": "制度/人事"}`，自动补上级）、删除（资料移回上一级） |
| `POST /collections/{cid}/folders/rename` | 重命名 / 移动整棵子树：`{"old", "new"}` |
| `PUT /collections/{cid}/documents/{doc_id}/folder` | 移动资料：`{"folder": "制度/人事"}`；目标不存在会自动创建 |
| `GET /collections/{cid}/audit` | 操作日志：最近 50 条，含操作人、动作、对象、时间；不记正文与请求头 |
| `GET /collections/{cid}/wiki` | Wiki 页面列表：标题、摘要、类型、文件夹、来源数、是否手改 |
| `POST /collections/{cid}/wiki/generate` | 从已完成资料生成 Wiki；模型不可用时按文档建页 |
| `GET /collections/{cid}/wiki/{page_id}` | 页面正文、类型、来源片段与反向链接；`can_write` 表示能否编辑 |
| `PATCH /collections/{cid}/wiki/{page_id}` | 编辑标题 / 类型 / 摘要 / 正文，旧版自动留档 |
| `DELETE /collections/{cid}/wiki/{page_id}` | 删除页面；来源资料不动 |
| `GET …/wiki/{page_id}/versions` / `GET …/versions/{id}` / `POST …/versions/{id}/restore` | 历史版本列表、单版详情与恢复 |
| `GET /collections/{cid}/wiki/entities` | 实体列表：名称、类型、摘要、来源数 |
| `GET /collections/{cid}/wiki/entities/{id}` | 实体详情：摘要、别名、来源片段、出现过的页面 |
| `GET /collections/{cid}/wiki/graph` | 关系图：页面 / 实体 / 来源资料节点；边含 `link` / `mention` / `folder` / `entity` / `source` / `entity_source` |
| `GET/POST/DELETE /collections/{cid}/members` | 公司库成员：添加 / 改角色 / 移除；个人库没有成员 |
| `POST /collections/{cid}/documents` | 粘贴资料：20–50000 字；重复回 409 |
| `POST /collections/{cid}/files` | 上传文件：请求体是文件，`X-Filename` 放 URI 编码后的文件名；原始字节与解析任务落库，返回 `processing` |
| `POST /collections/{cid}/documents/{doc_id}/retry` | 用保存的原始文件重新解析；重启或失败后使用 |
| `GET /collections/{cid}/documents/{doc_id}` | 资料原文（前端高亮引用原句） |
| `PATCH /collections/{cid}/documents/{doc_id}` | 整篇改标题 / 正文，保存前写历史版本 |
| `GET …/versions` / `GET …/versions/{id}` / `POST …/versions/{id}/restore` | 历史版本与恢复 |
| `GET …/chunks` / `PUT …/chunks/{chunk_id}` / `DELETE …/chunks/{chunk_id}` | 片段查看、修改（带 `revision` 乐观锁）、删除 |
| `POST …/reparse` | 用已存原文按当前切片参数重新切分 |
| `GET/POST/DELETE …/assets` | 插图与附件（按字节存） |

## 账号与同步

| 接口 | 说明 |
|---|---|
| `POST /auth/register` / `POST /auth/login` | 注册 / 登录，返回 `{"user", "token", "expires_at"}`；连续 5 次失败锁 10 分钟 |
| `POST /auth/logout` / `POST /auth/password` | 退出；改密码会作废其它设备会话 |
| `GET /auth/me` | 当前账号 |
| `GET/PATCH /admin/users` / `POST /admin/users/{id}/reset-password` | 管理员列表、改角色 / 停用、重置密码 |
| `GET/PUT/DELETE /me/data` | 个人数据同步：拉取、按时间戳合并、写墓碑删除 |

同步键接受 `yanju-*` 与旧的 `408-*`；凭据类键（访问口令、账号 token、同步元数据）服务端拒绝同步。

## 运维接口

| 接口 | 说明 |
|---|---|
| `GET /health` | 检索模式、provider、存储、知识库数量、Agent 与线程记忆类型 |
| `GET /version` | 版本、发布时间、最近的更新记录 |
| `GET /stats/overview` | 质量看板：进程内问答计数、缓存命中率、知识库规模、缺口与反馈 |
| `GET /stats/gaps` / `GET /stats/feedback` / `GET /stats/requests` | 缺口、反馈、请求日志 |
| `POST /create/outline` / `POST /create/export` | 创作大纲与 Word / PPT / Markdown 导出 |

## 访问口令与限流

设置 `KB_ACCESS_TOKEN` 后，内容接口都必须带 `X-Access-Token`；`/health`、`/version` 和静态页保持公开。`KB_RATE_MAX` / `KB_RATE_WINDOW` 控制问答接口的每 IP 限额（浏览知识库不占额度），`KB_DAILY_MAX` 是全局每日上限（0 为不限）。公网部署见 [部署.md](部署.md)。

`KB_REDIS_URL` 可选：多 worker 时把限流计数放进 Redis，没装 `redis` 包或连不上会自动退回进程内存。

拒绝回答会写入 `data/work/gap_log.jsonl`（`KB_GAP_LOG` 可改），记录 query、原因和最近命中片段；反馈有数据库时写 `answer_feedback`，没有数据库或写库失败时退到 `data/work/feedback.jsonl`。

# 在线问答与接口

前端与脚本调用的 HTTP 接口、启动方式、访问口令与限流规则。

## 启动

```bash
# 无 API key 先跑通链路：mock provider 只取 top-1 的答案，不是真生成
KB_MODE=hybrid KB_PROVIDER=mock py -m uvicorn api.app:app --host 127.0.0.1 --port 8000
# 浏览器打开 http://127.0.0.1:8000

# 接 DeepSeek；hybrid-ce 会自动启用标定过的拒答阈值 0.1/0
set DEEPSEEK_API_KEY=sk-xxxx          # PowerShell: $env:DEEPSEEK_API_KEY="sk-xxxx"
set KB_MODE=hybrid-ce
set KB_FUSE_K=10
set KB_CACHE_TTL=86400                # 应答缓存秒数，0 = 关闭
py -m uvicorn api.app:app --host 0.0.0.0 --port 8000
```

应答缓存只在配置了 `DATABASE_URL` 时生效，键由「检索模式 + provider + 精排候选数 + 语料指纹 + 归一化问题」组成；`/chat` 用改写后的问题查缓存。响应里的 `cached` / `cache_age_s` 标明是否命中及回答年龄，命中时 `trace` 只保留「应答缓存」一步。**拒答和寒暄/澄清不缓存**，避免把一次失败固化 24 小时。伙伴 / 人格 / 技能传入 `style` 时，缓存键会额外拼上 style 的 SHA-1 前缀：同一个问题换个伙伴会重新生成，不会串用别人的语气。

`style` 是可选字段（≤400 字），服务端会压成单行再注入 system prompt 的【讲解方式】段。该段明确写出「只影响措辞、语气和组织顺序，不得改变事实与结论，不得放宽引用要求，也不得引入资料以外的知识」；生成结果仍要过同一套逐字引用校验，校验失败照样重试一次、仍失败则拒答。

## 问题理解

后端在原有单轮链路前加了一层轻量 Agent：

1. 纯寒暄/“你能做什么”不检索，直接回固定说明；
2. 检测到「它 / 这题 / 那为什么 / 还有呢」等指代时，用 DeepSeek 结合最近 4 条消息改写成独立问题；
3. 改写失败或没有 key 时退回规则拼接，不影响答题；
4. 指代实在补不出来时返回“需要补充”，而不是猜。

## 接口一览

| 接口 | 说明 |
|---|---|
| `POST /ask` | 单轮问答：`{"query": "...", "style": "可选，≤400 字", "collection": "可选，自建知识库 id"}`，返回 answer / citations / refused / reason / hits / latency_ms / cached / cache_age_s；带 `collection` 且库不存在回 404 |
| `POST /chat` | 多轮问答：`{"query": "...", "history": [{"role": "user", "content": "..."}], "style": "可选，≤400 字", "collection": "可选"}`，额外返回 `intent`、`rewritten_query`、`trace.steps`；拒答时 `gap_detail` 是模型自己说出的缺口（系统判定码与空话为空串） |
| `POST /chat/stream` | 同参数的流式问答，返回 `text/event-stream`：`status`（plan / cache / retrieve / gate / generate / verify）、`delta`（增量文字，已从 JSON 里剥出 answer 字段）、`reset`（校验失败，清空已显示文字）、`error`、`done`（最终 payload，字段同 `/chat`）。校验未过时 `reset` → 重试一次 → 仍不过则 `done` 里是拒答 |
| `POST /agent/stream` | Agent 模式流式问答：`{"query", "thread_id": "可选", "history", "style", "collection"}`。事件：`status`（plan / search / tool / gate / generate / verify / retry / refuse / done）、`tool`（`search_kb` 的参数、命中数、耗时）、`delta`、`reset`（引用校验未过，换查询重试）、`error`、`done`（最终 payload，多带 `thread_id` / `tool_calls` / `agent`）。引用校验最多重试一次，仍不过拒答；线程记忆按 `thread_id` 存在内存或 PostgreSQL。现有 `/chat`、`/chat/stream` 不变。详见 [Agent 层](Agent层.md) |
| `POST /bank/generate` | 用资料出题：`{"text": "≥80 字的资料", "count": 5, "title": "资料标题"}`，返回 `{"questions": [...], "requested", "skipped", "notes"}`。每道题带 `options / answer / explanation / tags / source{title, quote, offset}`；`source.quote` 去空白后必须出现在 `text` 里，否则该题被丢弃并记进 `notes`。资料不落盘；离线演示模式返回 503 |
| `POST /mastery/turn` | 精通之路的导师会话，一轮一个请求（无状态）：`{"goal", "emoji", "subject", "materials": [{"key", "label", "kind", "detail"}], "learner": {prior/target/time/style}, "outline": {"name", "modules": [{id, name, objective, points: [{id, name, type, done}]}]}, "messages": [...], "message"}`，返回 `reply / ask / profile / outline / stage / offline / latency_ms`。`ask` 是 1–4 道带选项的提问卡（可为空），`outline` 只在模型给了合规大纲时出现（≥2 模块、≥4 知识点，最多 10 模块 / 48 知识点）。知识库与考点资料由服务端自己读，题库与对话由前端带上摘要。没有生成模型时走离线演示脚本，`offline: true` |
| `GET /collections` | 当前账号可见的自建知识库：公司库 + 自己的个人库；除 `documents` / `chunks` 外带 `visibility` / `my_role` / `can_write`，另有 `need_login` 与 `can_create_shared`（是否管理员）。408 题库不再作为知识库返回（v0.66）；未登录返回空列表并把 `need_login` 置真（线上开了访问口令时，不带口令的请求会先被 401 拦下，同样是读不到库） |
| `POST /collections` | 新建知识库：`{"name": "≤40 字", "description": "≤200 字", "visibility": "private|shared"}`，默认 `private`；建公司库要求管理员（403）；重名回 409 |
| `GET /collections/{cid}` | 知识库详情（含文档列表与权限字段）；无权回 404 |
| `DELETE /collections/{cid}` | 删除知识库：连文档、片段和成员一起删；只有管理员 / 建库人（`can_manage`）能做，editor 也不能删库；内置库 403，无权 404 |
| `GET /collections/{cid}/members` | 公司库成员：`{owner, items: [{user_id, username, role}]}`；个人库回 400，editor / viewer 无权（404） |
| `POST /collections/{cid}/members` | 添加或改角色：`{"username": "对方用户名", "role": "editor|viewer"}`；建库人 / 自己 / 不存在的用户分别回 400 / 400 / 404 |
| `DELETE /collections/{cid}/members/{user_id}` | 移除成员；不能移除建库人（400） |
| `POST /collections/{cid}/documents` | 加资料：`{"text": "20–50000 字", "title": "可选，≤80 字"}`，返回切出的片段数；同一份资料重复添加回 409 |
| `GET /collections/{cid}/documents/{doc_id}` | 资料原文（前端用来高亮引用原句）；解析中的文档回 409，失败的回 404 并带原因 |
| `DELETE /collections/{cid}/documents/{doc_id}` | 删除一篇资料，删完该库的检索索引随之失效重建 |
| `POST /collections/{cid}/files` | 上传原始文件：请求体是文件本身，`X-Filename` 放 URI 编码后的文件名，单个 ≤20MB；本地解析，立即返回 `processing` 文档，失败原因写进 `status: failed` |
| `GET /collections/{cid}/documents/{doc_id}/chunks` | 资料切出的片段（含 `seq` / `text` / `revision`），附 `editable`：只读成员能看片段但不能改 |
| `PUT /collections/{cid}/documents/{doc_id}/chunks/{chunk_id}` | 改片段正文：`{"content": "...", "revision": 3}`（10–4000 字）；`revision` 是乐观锁，冲突回 409 |
| `DELETE /collections/{cid}/documents/{doc_id}/chunks/{chunk_id}` | 删片段，删完该库检索缓存失效 |
| `POST /collections/{cid}/documents/{doc_id}/reparse` | 用已存原文重新切分；没有可切分的原文时回 400 并提示重新上传 |
| `GET /stats/requests` | 请求日志：`days` / `limit`，返回总数、按路径（次数 / 平均耗时 / 5xx）、按天与最近请求 |
| `GET /eval/results` | 评测结果列表：`name` / `limit`；`POST` 同路径写入一次评测摘要（需 `DATABASE_URL`） |
| `GET /chunks` | 题库列表：`q` / `subject` / `year` / `limit` / `offset`，只返回题干和选项 |
| `GET /chunks/{id}` | 题目详情：题干、选项、答案、解析、`source_ref`、`related_knowledge` |
| `GET /knowledge` | 考点列表：`q` / `subject` / `chapter` / `limit` / `offset`，附带科目计数和章节计数 |
| `GET /knowledge/tree` | 考点树 + 考频榜：科目 → 章节（考点数 / 涉及真题数），`heat` 按关联真题数排序，`limit` 控制榜单条数 |
| `GET /knowledge/{id}` | 考点详情：正文、公式、易错点、来源行号、关联真题 |
| `GET /graph` | 知识图谱：节点（考点卡 / 真题）、边（卡片写明的关联）、科目 / 年份 / 孤立题筛选所需计数；`orphans=1` 连未配考点的真题一起返回 |
| `POST /feedback` | 回答反馈：`{"query": "...", "helpful": true|false, "reason": "...", "note": "...", "answer": "...", "citations": ["2019-408-01"], "cached": false}`；不占问答额度。前端评分入口已撤掉，接口保留给后续分析 |
| `GET /stats/gaps` | 缺口统计：`days` / `limit`，返回总数、按原因、按天、最近拒答 |
| `GET /stats/feedback` | 反馈统计：`days` / `limit`，返回总数、有帮助率、按差评原因、最近差评 |
| `GET /stats/overview` | 质量看板数据：进程内问答计数、缓存命中率、语料规模，外加同窗口的缺口与反馈统计 |
| `GET /meta` | 题目数、科目分布、年份、考点数、检索模式 |
| `GET /health` | 题目数、考点数、检索模式、provider；`agent` / `agent_checkpointer` 表示 Agent 是否启用、线程记忆落在内存还是 Postgres |
| `POST /auth/register` | 注册并登录：`{"username": "2–24 字", "password": "≥8 位"}`；重名回 409，用户名大小写不敏感 |
| `POST /auth/login` | 登录：同上，返回 `{"user", "token", "expires_at"}`；连续 5 次密码错误后同 IP + 用户名锁 10 分钟（429）；会话 30 天滑动过期，每次带 token 使用都会顺延（一天内最多写一次库） |
| `POST /auth/logout` | 退出登录，作废当前 `Authorization: Bearer <token>` |
| `POST /auth/password` | 改密码：`{"old_password", "new_password"}`；原密码错走同一套失败计数（429），改完其它设备的会话全部作废、当前 token 保留，返回 `sessions_revoked` |
| `GET /auth/me` | 当前账号：`{"user": {id, username, role, disabled, created_at, last_login_at}}`；`role` 为 `admin` / `member`；token 无效回 401 |
| `GET /admin/users` | 管理员列账号：`{"users": [...]}`，按注册时间排列；非管理员回 403，停用账号的 token 直接失效 |
| `PATCH /admin/users/{id}` | 管理员改角色 / 停用：`{"role": "admin" / "member", "disabled": true / false}`，只改传上来的字段；不能改自己，至少保留一个可用管理员，停用会立刻作废对方所有会话 |
| `POST /admin/users/{id}/reset-password` | 管理员重置别人的密码：可传 `{"new_password": "..."}`，不传则生成 12 位临时密码；返回 `{"user", "temp_password"}`，临时密码只此一次；会作废对方所有会话，不能重置自己 |
| `GET /me/data` | 拉取账号下的个人数据：`{"items": {key: {value, updated_at}}}`；`value` 是 localStorage 里的原字符串 |
| `PUT /me/data` | 按时间戳合并：`{"items": {key: {value, updated_at}}}`，比服务器旧的不覆盖，返回被拒键的服务器时间 |
| `DELETE /me/data` | 删除同步副本：`{"all": true}` 或 `{"keys": ["408-..."]}`；写墓碑，别的设备下次同步会删本地那份 |
| `GET /` | 对话优先的前端：默认问答，主导航问答 / 学习 / 学习空间 / 创作 / 任务清单，质量看板在设置内，可直接在手机上打开 |

## 访问口令、限流与环境变量

设置 `KB_ACCESS_TOKEN` 后，内容接口（`/ask`、`/chat`、`/chat/stream`、`/agent/stream`、`/bank/generate`、`/mastery/turn`、`/feedback`、`/chunks`、`/knowledge`、`/collections` 及其子路径、`/auth/*`、`/admin/users`、`/me/data`、`/meta`、`/stats/gaps`、`/stats/feedback`、`/stats/overview`）都必须带
`X-Access-Token`；`/health` 和静态页保持公开。`KB_RATE_MAX` / `KB_RATE_WINDOW` 控制问答接口的每 IP
限额（刷题库/知识库不占额度），`KB_DAILY_MAX` 是全局每日上限（0 为不限）。公网部署见 [部署.md](部署.md)。

通用回答与日常对话用的网页搜索默认走免密钥的 Bing RSS；要换更稳的搜索 API，在服务端环境变量里配
`SEARCH_PROVIDER`（`tavily` / `serper` / `bing`）和 `SEARCH_API_KEY`，密钥只留在环境变量里。
七个工具都在设置页开关，只在资料里查不到依据、改走通用回答时生效（`mode=auto` 的兜底分支与旧版 `mode=chat`），资料有依据时不调用。`KB_REDIS_URL` 可选：多 worker 时把限流计数放进 Redis，没装 `redis` 包或连不上会自动退回进程内存。

考点文件默认读 `data/curated/knowledge.jsonl`，可用 `KB_KNOWLEDGE` 指向别的 JSONL。启动时会校验
`id / subject / chapter / title / body` 必填字段，并检查考点 id 不能和题目 id 冲突；同一 id 后出现的覆盖先出现的。

引用会带 `source_ref`（原文件 + 行号），拒答会写入 `data/work/gap_log.jsonl`（`KB_GAP_LOG` 可改），记录 query、拒答原因和最近命中题，作为补资料的输入。反馈有数据库时写 `answer_feedback` 表，没数据库或写库失败时退到 `data/work/feedback.jsonl`（`KB_FEEDBACK_LOG` 可改），不丢用户的操作。

## 回答链路

链路是：理解问题（可选改写）→ 检索 → 拒答闸门 → 生成（强制 JSON）→ 引用逐字校验 → 失败重试一次 → 仍失败降级为拒答。
默认（`mode=auto`）在闸门判定资料不足时改走通用回答：写明「资料里没有直接依据」、不带引用、记缺口、不写缓存；引用校验失败与生成服务异常仍拒答。

用户点名题号时（`2019-408-10`、`2019 年第 10 题`），检索会直接锁定该题并给 1.0 分，不依赖关键词召回；如果库里没有这个年份或题号，直接返回空结果拒答，不会拿别的题顶替。
